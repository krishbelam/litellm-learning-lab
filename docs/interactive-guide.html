2. Explore the three demos

Basic chat: one stable API endpoint

The client sends a model alias, messages, and a LiteLLM virtual key. LiteLLM checks the key and forwards the request to the upstream model configured under that alias.

client = OpenAI(
    api_key=LITELLM_VIRTUAL_KEY,
    base_url="http://localhost:4000/v1"
)
client.chat.completions.create(
    model="local-llama",
    messages=[{"role":"user","content":"Hello"}]
)

Key distinction: the virtual key authenticates the application to LiteLLM. It is not an OpenAI provider API key.

Model routing: aliases hide provider details

The app asks for local-llama. LiteLLM maps that alias to ollama_chat/llama3.2. If enabled, cloud-gpt can map to an OpenAI model. The client code stays OpenAI-compatible.

model_list:
  - model_name: local-llama
    litellm_params:
      model: ollama_chat/llama3.2
      api_base: http://host.docker.internal:11434

  # Optional cloud route:
  # - model_name: cloud-gpt
  #   litellm_params:
  #     model: openai/gpt-4.1-mini
  #     api_key: os.environ/OPENAI_API_KEY

Aliases are the names applications request. The provider model and connection settings are configured on the proxy.

Rate limits: policy belongs at the gateway

Create a dedicated virtual key or test team and configure a low requests-per-minute (RPM) limit. Then run demos/03_rate_limits.py with concurrent calls.

export LITELLM_VIRTUAL_KEY="your-test-key"
export REQUEST_COUNT=12
export MAX_WORKERS=8
python demos/03_rate_limits.py

When the configured limit is reached, some requests may receive HTTP 429. Concurrency alone does not create a limit; the key or team must have a limit configured.

5. Local-only vs cloud-enabled

Local-only Ollama runs on your host. Pull a model, make its API reachable from Docker, and configure the Ollama model alias. No OpenAI provider key is needed.
Cloud-enabled Add your own OpenAI provider key to the proxy environment, enable the cloud model entry, and ensure the virtual key is allowed to use that alias.

Never confuse the two credentials: client → LiteLLM uses a LiteLLM virtual key; LiteLLM → OpenAI uses your OpenAI provider key. Ollama local calls do not require an OpenAI key.

6. Commands worth remembering

# Check the proxy container and logs
docker compose ps
docker compose logs --tail=200 litellm

# Check Ollama on the host
ollama list
ss -lntp | grep 11434
curl http://localhost:11434/api/tags

# Linux manual Ollama launch, reachable from Docker
OLLAMA_HOST=0.0.0.0:11434 ollama serve

# Recreate proxy after Compose networking changes
docker compose up -d --force-recreate litellm

If tools such as curl or getent are missing inside a minimal container, that alone does not prove the network is broken. Use a temporary diagnostic container or Python's standard library where available.
